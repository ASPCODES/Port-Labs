// Lab: User ID controlled by request parameter, with unpredictable user IDs



This lab has a horizontal privilege escalation vulnerability on the user account page, but identifies users with GUIDs.

To solve the lab, find the GUID for carlos, then submit his API key as the solution.

You can log in to your own account using the following credentials: wiener:peter.





Hints: 

In some applications, the exploitable parameter does not have a predictable value. For example, instead of an incrementing number, an application might use globally unique identifiers (GUIDs) to identify users. This may prevent an attacker from guessing or predicting another user's identifier. However, the GUIDs belonging to other users might be disclosed elsewhere in the application where users are referenced, such as user messages or reviews.




Solution:


1. Look for the blog post by carlos, which contains his GUID in the URL. The URL is in the format /blog/post?postId=GUID, which can be found in the URL of the blog post.

https://www.target.com/blog/post?userId=53acc38a-d756-4540-bd23-63424d2cf365


2. Copy the GUID from the URL and note it down.


3. Now, login to your account using the provided credentials (wiener:peter).


4. Change the userId parameter in the URL from wiener's GUID to carlos's GUID. This will allow you to access carlos's account.


5. Once you have access to carlos's account, YOU can find his API key on the account page. Copy the API key.


6. Submit carlos's API key as the solution to the lab.
