// Lab: User ID controlled by request parameter with data leakage in redirect.



This lab contains an access control vulnerability where sensitive information is leaked in the body of a redirect response.

To solve the lab, obtain the API key for the user carlos and submit it as the solution.

You can log in to your own account using the following credentials: wiener:peter.




// Solution:

Step 1 — Log in

Open the lab and log in using the provided credentials (e.g., wiener:peter).



Step 2 — Visit the account page

You should see a URL like /my-account?id=wiener.
Intercept this request with Burp Suite.



Step 3 — Send to Burp Repeater

In Burp Suite, go to Proxy → HTTP History and find that request.
Right-click and choose "Send to Repeater."



Step 4 — Modify the id parameter

In the Repeater tab, change id=wiener to id=carlos in the request.
Click Send.



Step 5 — Review the response

The response will be a 302 redirect (to the home page),
but the body contains Carlos's API key.
Copy it and submit it as the lab solution.
