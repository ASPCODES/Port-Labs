// Lab: Authentication bypass via OAuth implicit flow

This lab uses an OAuth service to allow users to log in with their social media account. Flawed validation by the client application makes it possible for an attacker to log in to other users' accounts without knowing their password.

To solve the lab, log in to Carlos's account. His email address is carlos@carlos-montoya.net.

You can log in with your own social media account using the following credentials: wiener:peter.




// solution


1. Open the lab and click **My Account**.

2. Log in using the OAuth account:

   * **Username:** `wiener`
   * **Password:** `peter`

3. After login, go to **Burp Suite → Proxy → HTTP History**.

4. Find the **`POST /authenticate`** request.

5. Right-click the request and select **Send to Repeater**.

6. In Repeater, change only the `email` value:

   ```
   From:
   "email":"wiener@..."

   To:
   "email":"carlos@carlos-montoya.net"
   ```

7. Do **not** change the `username` or `token`.

8. Click **Send**.

9. If the response returns **`HTTP/2 302 Found`** with a **`Set-Cookie`** header, the request has been accepted.

10. Right-click the modified request and select:

    ```
    Request in browser
        ↓
    In original session
    ```

11. Copy the generated URL and open it in your browser.

12. The browser uses the new session cookie, logs you in as **Carlos**, and the lab is solved.
